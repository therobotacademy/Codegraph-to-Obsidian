# Obsidian Codebase Vault Cheatsheet

This guide covers exploring, auditing, and annotating the codebase as an interactive **Personal Knowledge Graph** using the Obsidian vault generated by `.codegraph/export_obsidian.py`.

---

## 1. Architectural Paradigm: Codebase as Knowledge Graph

Traditional code exploration forces a choice between **linear file reading** (top-to-bottom) and **point queries** (`grep`, `find`).

By exporting `codegraph.db` into Obsidian under the **OKF v0.2** (*Open Knowledge Framework*) schema, the codebase is transformed into a navigable, force-directed network where:

* Every **class, function, method, and file** is an independent Markdown note.
* AST relationships (`calls`, `defines`, `imports`, `overrides`) become bidirectional **wikilinks** (`[[target|label]]`).
* Callers and dependencies are traced in real time using graph views, hover previews, and backlinks.
* Human architectural notes, thesis cross-references, and governance audit findings can be attached directly to symbols without modifying source code.

## 5. Visual Graph Exploration

Obsidian's graph views are pre-configured via `.obsidian/graph.json` with semantic type coloring:

### Semantic Color Coding

| Node Type                   | Color Hex   | Color Preview | Description                                  |
| :-------------------------- | :---------- | :------------ | :------------------------------------------- |
| **`code/file`**     | `#EB082E` | 🔴 Red        | Source code files and module indices         |
| **`code/class`**    | `#F59E0B` | 🟠 Amber      | Object definitions, protocols, domain models |
| **`code/function`** | `#06B6D4` | 🔵 Cyan       | Standalone functions, normalizers, utilities |
| **`code/method`**   | `#0BFEAD` | 🟢 Mint Green | Member functions, class methods              |
| **`code/variable`** | `#F7FF0E` | 🟡 Yellow     | Module constants, global singletons          |
| **`index`**         | `#94A3B8` | ⚪ Slate      | Root and directory index notes               |

---

### A. Global Graph (`Ctrl + G`)

The global graph displays the macroscopic architecture of the entire repository:

1. **Identifying Architecture Hubs**: Dense clusters of incoming/outgoing arrows indicate core orchestrators (e.g. `GovernanceEngine`, `MockErpConnector`).
2. **Identifying Decoupled Modules**: Isolated node clusters indicate self-contained sub-libraries (e.g. `normalize.py` or `fatura/parser.py`).
3. **Filtering the Global Graph**:
   Use the Filter panel (top-right of graph):
   * **Show only Classes**: `tag:#code/class`
   * **Isolate Perception Layer**: `path:src/govagent/perception`
   * **Exclude Test Files**: `-path:tests`
   * **Hide Orphans**: Toggle *Hide Unresolved Links* or set minimum link threshold.

---

### B. Local Graph (Neighborhood Call Tracing)

The **Local Graph** is the most effective tool for day-to-day code inspection:

1. Open any symbol note (e.g., `ConsequenceBasedAuthoritySpec.md`).
2. Open Command Palette (`Ctrl + P`) $\to$ search **"Open local graph"** (or drag the Local Graph tab to your right sidebar).
3. **Adjust Depth (Jumps)**:
   * **Depth = 1**: Shows direct callers and direct callees.
   * **Depth = 2**: Traces two steps into the call graph (who calls my caller? what do my dependencies invoke?).
4. **Incoming vs Outgoing**: Toggle arrows in Local Graph display settings to follow execution flow forwards or backwards.

## 6. Daily Navigation & Power Shortcuts

| Shortcut               | Action                            | Code Exploration Purpose                                                                 |
| :--------------------- | :-------------------------------- | :--------------------------------------------------------------------------------------- |
| `Ctrl + O`           | **Quick Switcher**          | Fuzzy search any class or function across the entire codebase instantly.                 |
| `Ctrl + P`           | **Command Palette**         | Execute commands (toggle graph, split panes, canvas).                                    |
| `Ctrl + Click`       | **Open in New Tab / Split** | Open caller and callee side-by-side to cross-check interfaces.                           |
| `Ctrl + Hover`       | **Page Preview**            | Hover over any`[[link]]` to inspect signatures and docstrings without leaving context. |
| `Alt + Left / Right` | **History Back / Forward**  | Step backwards and forwards through your exploration path.                               |
| `Ctrl + F`           | **Find in File**            | Search within the current symbol's relationships.                                        |
| `Ctrl + Shift + F`   | **Global Vault Search**     | Full-text search across all docstrings, tags, and signatures.                            |

## 7. Advanced Code Analysis with Obsidian Dataview

If you install the popular community plugin **Dataview** (*Settings $\to$ Community Plugins $\to$ Turn on Community Plugins $\to$ Search 'Dataview'*), you can write dynamic SQL-like queries directly in Markdown.

### Recipe 1: List All Classes in a Given Subsystem

```dataview
TABLE description, file_path, start_line
FROM #code/class
WHERE contains(file_path, "perception")
SORT file_path ASC
```

### Recipe 2: Find Symbols Lacking Docstrings

```dataview
TABLE file_path, start_line
FROM #code/function OR #code/class
WHERE description = "" OR contains(description, "function ") OR contains(description, "class ")
SORT file_path ASC
```

### Recipe 3: Audit Highly Connected Architectural Interfaces

```dataview
TABLE length(file.inlinks) AS "Incoming Callers", length(file.outlinks) AS "Outgoing Calls"
FROM #code/class
SORT length(file.inlinks) DESC
LIMIT 15
```

Obsidian Canvas lets you arrange symbol notes onto an infinite visual whiteboard:

1. Right-click any folder or empty area $\to$ **New Canvas** (e.g. `perception_architecture.canvas`).
2. Drag and drop symbol notes (`VLMExtractor.md`, `PerceptionResult.md`, `rebuild.md`) directly onto the canvas.

## 9. Attaching Human Knowledge & Audit Annotations

The greatest advantage of the vault over static AST dumps is **knowledge persistence**:

### Adding Auditor Callouts

You can open any generated note (e.g., `AuthoritySpec.md`) and append human analysis at the bottom:

```markdown
---
## Human Governance Audit (Phase 3 Review)

> [!IMPORTANT]
> This class implements the primary non-delegation invariant (Constitution Article II). 
> Any modification to `evaluate()` must verify zero regression against `test_authority.py`.

### Pending Investigation
- [ ] Check how boundary offset `0.01` EUR is handled in `cap-above` vs `cap-below`.
- [ ] Cross-check with thesis chapter 02 on perception drift.
```

### Tagging for Audits and Reviews

Add custom tags to a note's YAML frontmatter:

```yaml
tags:
  - code/class
  - audit/p1
  - review/pending-test
```

You can now search for `tag:#review/pending-test` to get an instant checklist of components requiring scrutiny.

## 10. Re-generation & Vault Refresh

When you modify code and re-run the export script:

```bash
# Rebuild CodeGraph SQLite database
codegraph init

# Refresh the Obsidian vault
python .codegraph/export_obsidian.py --out .codegraph/67-obsidian_vault
```

> [!TIP]
> If you plan to add extensive personal notes to generated files, consider using separate notes (e.g., `Audit_GovernanceEngine.md`) that link to `[[GovernanceEngine]]`, or store personal reflections in dedicated audit folders to avoid overwrite conflicts during batch re-exports.
