# Obsidian Dataview Codebase Queries

## Overview

When exploring or auditing a codebase, answering questions via chat creates disposable text that quickly becomes obsolete.

This skill provides a systematic pattern for generating **living, persistent query notes** inside an **OKF v0.2 / CodeGraph** Obsidian vault (e.g. `.codegraph/67-obsidian_vault/queries/`). These notes use the **Dataview** plugin to dynamically query the code graph's metadata, staying continuously synchronized with codebase changes while providing clickable, spatial navigation for the user.

---

## When to Use This Skill

* The user asks architectural, structural, or dependency questions about the codebase (e.g., *"Show me all perception classes and what calls them"*, *"Which modules have high inbound coupling?"*, *"Find all boundary test cases"*).
* The user wants an audit checklist or dynamic index for a subsystem.
* You need to deliver an interactive dashboard that can be embedded into an Obsidian Canvas or architectural report.

## Vault Metadata Contract (OKF v0.2)

Every symbol note generated by `export_obsidian.py` contains standard YAML frontmatter and native Obsidian attributes that Dataview can query:

### Note Frontmatter Fields

| Field           | Type    | Description                    | Example                                                                                        |
| :-------------- | :------ | :----------------------------- | :--------------------------------------------------------------------------------------------- |
| `type`        | string  | Symbol category                | `"code/class"`, `"code/function"`, `"code/method"`, `"code/file"`, `"code/variable"` |
| `file_path`   | string  | Relative source file path      | `"src/govagent/engine.py"`                                                                   |
| `start_line`  | integer | Starting line number in source | `45`                                                                                         |
| `end_line`    | integer | Ending line number in source   | `130`                                                                                        |
| `description` | string  | Sanitized docstring header     | `"Core event dispatcher..."`                                                                 |
| `resource`    | string  | Direct URI to source code      | `"file:///src/govagent/engine.py#L45-L130"`                                                  |
| `tags`        | list    | Semantic tags                  | `["code/class"]`, `["code/function"]`                                                      |
| `aliases`     | list    | Symbol aliases                 | `["GovernanceEngine", "govagent.engine.GovernanceEngine"]`                                   |

### Native Dataview Page Attributes

* `file.link`: Clickable wikilink to the symbol note.
* `file.inlinks`: Array of incoming links (callers, referrers).
* `file.outlinks`: Array of outgoing links (callees, dependencies).
* `file.folder`: Directory of the note (e.g., `"src/govagent/perception/golden.py"`).

## Workflow: Creating a Query Node

### Step 1: Isolate the Destination

Always save query notes in a dedicated queries folder inside the vault:

```text
<VAULT>/queries/<topic-slug>.md
```

> [!IMPORTANT]
> Never write query notes into `src/` or `tests/` folders inside the vault to prevent collisions with `export_obsidian.py`.

### Step 2: Choose Query Engine (DQL vs DataviewJS)

* **Dataview Query Language (DQL)**: Best for filtering, sorting, grouping, and rendering tables of symbols.
* **DataviewJS**: Best for multi-hop link traversal, recursive dependency walks, or programmatic graph filtering.

### Step 3: Author the Query Note Structure

A well-structured query note contains:

1. **Frontmatter**: Typed as `type: "view/query"`.
2. **Context / Objective**: What question this note answers.
3. **Live Dataview Code Block(s)**: Filtered query expressions.
4. **Agent Synthesis**: Concise explanation of architectural findings, invariants, and observations.

## DQL Query Recipes

### 1. Subsystem Symbol Catalog

List all classes within a specific module sorted by caller density:

```dataview
TABLE description AS "Docstring", file_path AS "Source", length(file.inlinks) AS "Callers"
FROM #code/class
WHERE contains(file_path, "perception")
SORT length(file.inlinks) DESC
```

### 2. High Inbound Coupling (Architectural Hotspots)

Identify classes or functions with large inbound call footprints:

```dataview
TABLE length(file.inlinks) AS "Inbound Callers", file.inlinks AS "Called By"
FROM #code/class OR #code/function
WHERE length(file.inlinks) >= 5
SORT length(file.inlinks) DESC
```

### 3. Normalization & Utility Audit

Survey utility functions and their source lines:

```dataview
TABLE start_line AS "Line", description AS "Function Purpose"
FROM #code/function
WHERE contains(file_path, "normalize")
SORT start_line ASC
```

### 4. Cross-Module Dependency Check

Find symbols that depend on a specific external subsystem (e.g. ERP connectors):

```dataview
TABLE file.folder AS "Module", length(file.outlinks) AS "Total Calls"
FROM "src/govagent"
WHERE any(file.outlinks, (out) => contains(out.path, "connectors"))
```

## DataviewJS Recipes (Advanced Graph Traversal)

### Multi-Hop Call Path Tracing

Find all classes that directly or indirectly reference a target class:

```javascript
```dataviewjs
const targetPath = "src/govagent/connectors/mock_erp.py/MockErpConnector";
const callers = dv.pages("#code/class")
    .where(p => p.file.outlinks.some(l => l.path.includes("MockErpConnector")));

dv.table(
    ["Class", "File Path", "Docstring"],
    callers.map(p => [p.file.link, p.file_path, p.description])
);

  - query/[topic]

> **Objective**: [1-sentence explanation of what this dashboard tracks].

## Live Symbol Index

```dataview
TABLE description AS "Description", file_path AS "Path", length(file.inlinks) AS "Refs"
FROM #code/class
WHERE contains(file_path, "[subsystem]")
SORT length(file.inlinks) DESC
```

## Outgoing Call Traversal

```dataview
TABLE file.outlinks AS "Dependencies"
FROM "[subsystem-path]"
WHERE length(file.outlinks) > 0
```

## Architectural Synthesis

- **Primary Abstractions**: Identify the root protocols or base classes.
- **Invariants Observed**: Note boundary protections, immutability, or isolation rules.
- **Audit Flags**: Highlight any high-coupling, missing docstrings, or circular call patterns.
